# 信息加工 workflow

## 目标
自己的近期订阅接入本地OpenCode常态加工；上游加工增加事件候选召回与重复事件检查。统一入口名为workflow，替换原local-processing timer，区分遗留cron。

## 复用与边界
复用systemd timer、Python stdio桥、AIHOT评分/摘要/事件归组与publication层，不新增调度平台。模型固定MiniMax3.1，共享300/24h、60/h、8/min；无通知，X搜索保持暂停，历史不批量重算，网页不改。

## 实施
1. 扩大自己的订阅选择范围，过滤历史、暂停源、失败/未知回执及人工处理。
2. 增强事件候选召回，用原标题、加工标题与摘要比较；同事件无新增事实留待审。
3. 单一workflow脚本串行处理原生及上游批次，记录实际运行结果，替换旧timer。
4. 行为测试、436部署、真实加工回执与公网站点读回验收。
