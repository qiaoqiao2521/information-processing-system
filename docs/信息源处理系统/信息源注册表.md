# 信息源注册表

## 注册表口径

每一行代表一个可维护的信息源、采集编排层，或信息处理链路。

关键字段说明：

- `source_of_truth`: 真正可信的上游。
- `access_path`: 本机访问这个上游的工具或脚本。
- `acquisition_recipe`: 公开网页 / X / 单链接内容进入编排层时采用的规则集。
- `adapter_set`: recipe 允许调用的 adapter 集合。
- `ledger`: 每次 acquisition run 的尝试、结果、停止原因和提升决定。
- `contract`: 这个任务承诺产出什么。
- `failure_behavior`: 上游失败时应该如何处理。

## Target Layer Split

后续目标不是继续扩展单张“信息源”表，而是拆成两层：

| 大层 | 包含 | 边界 |
| --- | --- | --- |
| 信息获取层 | collector, acquisition orchestrator, selector, knowledge pack | 输出标准 `knowledge_pack`，不创建 NotebookLM notebook |
| 知识消化层 | NotebookLM ingest, report, artifact, publishing | 消费标准 pack，不直接抓上游 source |

采集编排层内部建议继续拆成：

| 子层 | 职责 | 输出 |
| --- | --- | --- |
| source collectors | 产生原始条目、URL、正文或 manifest | raw entries / manifests |
| acquisition recipes | 决定不同 item type 的抓取策略与允许 adapter | recipe selection |
| acquisition adapters | 执行 reader / browser / crawl / extract 行为 | attempt results |
| acquisition ledger | 记录 attempts、selected result、promotion notes | run ledger JSON |
| promotion into `knowledge_pack` | 把稳定结构化结果转成 canonical items | `knowledge_pack` candidates / items |

## 维护规则

1. 新增采集 cron 时，先补本表，再创建或修改任务。
2. 修改任务输出路径时，同步更新 `canonical outputs`。
3. 如果任务只是下游加工，不要放进 `Active Sources`，放进 `Downstream Consumers`。
4. 如果任务是额度、健康、账号池、同步类，不要放进内容信息源表，放进 `Excluded Ops Telemetry`。
5. 如果任务是 APD 这类流水线实现骨架，不要放进 `Active Sources`，放进 `Pipeline Engines`。
6. NotebookLM 相关消费者后续应优先读取 `knowledge_pack_latest.json`，而不是直接绑定某一个 source manifest。
7. 公开网页 / X 的抓取策略要登记为 acquisition recipe + adapter set，而不是只写单个 fallback_tool。
8. Firecrawl / web-agent 只能登记在 `Candidate Adapters`，不能登记到 `Active Sources`。
